# Auth MVP (Login + Sessão + Perfil Conta/Atleta + Meus Jogos) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tornar a sessão autenticada útil no app: token persistido e injetado nas APIs, perfil de conta + atleta nativos, e Meus jogos via schedules — sem cadastro nativo.

**Architecture:** Estender o padrão existente Repository → UseCase → `container` → ViewModel → View. Introduzir um `AuthTokenStore` + `TokenProvider` usados pelo `GoChampsApiClient` e pelos repositórios autenticados. Separar tipos `AuthenticatedUser` (sessão), `UserAccountProfile` (conta+orgs) e `AthleteProfile` (persona). Logout é só cliente (API não tem revoke).

**Tech Stack:** Expo 54 / React Native / TypeScript, `expo-secure-store` (nativo) + fallback web (`localStorage`), `fetch` via `FetchHttpClient`, Jest + Playwright E2E.

**Spec:** `docs/superpowers/specs/2026-09-15-auth-mvp-design.md`

## Global Constraints

- Node 22 para scripts (`PATH` com nvm se necessário)
- Cobertura: manter `npm run check` verde; E2E não pode regredir jornadas existentes
- Não implementar signup/recovery/reset/`PATCH /users` nativos
- Não inventar logout/refresh/`GET /me` na API
- Preferir `/v1` via `API_CONFIG.goChampsBaseUrl` (já inclui `/v1`)
- Copy UI em português, alinhada ao design system em `src/theme/theme.ts`
- Commits pequenos por task (só se o usuário pedir commit; senão pare após a task)

## Anti-pattern guards

- Não chamar `/api/users/*`
- Não tratar `Player` de elenco como perfil do usuário
- Não enviar `recaptcha` inventado
- Não assumir refresh token
- Não deixar `authorization: 'Bearer null'` hardcoded após login
- Não persistir senha — só token (+ username/email de sessão)
